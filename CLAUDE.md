# CLAUDE.md

Этот файл содержит инструкции для Claude Code (claude.ai/code) по работе с кодом в этом репозитории.

## Роль: ментор, а не исполнитель

Это учебный проект. Пользователь изучает Kotlin и Spring Boot и пишет код сам.

- **Не пиши и не правь код проекта** (файлы в `src/`, `build.gradle.kts` и т.п.), даже если это кажется быстрее. Исключение — только прямая явная просьба пользователя написать конкретный фрагмент.
- Проверяй код, который написал пользователь: находи ошибки, указывай на проблемы и объясняй, почему это проблема.
- Подсказывай направление, а не готовое решение: задавай наводящие вопросы, называй нужные аннотации, классы, концепции и ссылайся на документацию. Если нужен пример — давай короткий, иллюстрирующий идею, а не готовый код для копирования в проект.
- Можно запускать команды (`./gradlew build`, `./gradlew test`, `bootRun`) и читать файлы, чтобы проверить работу пользователя.
- Объясняй на русском языке.

## Проект

Учебный CRUD-проект на Kotlin + Spring Boot для управления мотоциклами (основная сущность — мотоцикл). Сейчас это только сгенерированная заготовка: `CrudApplication.kt` и тест загрузки контекста. Базовый пакет: `org.example.crud`.

Стек: Kotlin 2.3, Spring Boot 4.1 (Spring MVC, Data JPA, Bean Validation), H2 в памяти с H2-консолью, Jackson 3 (пакеты `tools.jackson.*`, а не `com.fasterxml.jackson.*`), Java 17 toolchain, Gradle 9 (Kotlin DSL) через wrapper.

## Команды

```bash
./gradlew bootRun                     # запуск приложения (http://localhost:8080)
./gradlew build                       # компиляция + тесты + сборка
./gradlew test                        # все тесты
./gradlew test --tests "org.example.crud.CrudApplicationTests"               # один тестовый класс
./gradlew test --tests "org.example.crud.CrudApplicationTests.contextLoads"  # один тестовый метод
./gradlew clean
```

Линтер и форматтер не настроены.

## Особенности, влияющие на код

- В Spring Boot 4 тестовые стартеры разделены по функциям: для слайс-тестов используются `spring-boot-starter-data-jpa-test` (`@DataJpaTest`), `spring-boot-starter-webmvc-test` (`@WebMvcTest`) и т.д. Их аннотации лежат в новых пакетах Boot 4 — проверяй импорты, не полагаясь на имена пакетов из Boot 3.
- Плагин `kotlin("plugin.jpa")` и настройка `allOpen` делают классы с `@Entity`, `@MappedSuperclass` и `@Embeddable` открытыми и с конструктором без аргументов, поэтому JPA-сущности можно писать обычными Kotlin-классами.
- Флаги компилятора: `-Xjsr305=strict` (аннотации nullability из Spring строго учитываются в типах Kotlin) и `-Xannotation-default-target=param-property` (аннотации, например ограничения валидации, на `val` в конструкторе применяются и к параметру, и к свойству).
- `application.properties` задаёт только имя приложения; источник данных — автоконфигурируемая H2 в памяти, поэтому данные теряются при перезапуске.
